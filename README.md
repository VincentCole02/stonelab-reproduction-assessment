# StoneLab Reproduction assessment

这是一份用于评估论文或研究项目复现难度的 Codex Skill。准备复现时，论文、仓库和实际可运行的实验之间常有距离：代码可能缺少训练或评估脚本，数据和权重也可能需要单独申请。这个 Skill 会核查这些条件，帮助你判断需要投入多少工作，以及先做哪一步最能减少不确定性。

## 它评估什么

评估分成两条路径。一条是运行或修改作者代码，重点检查仓库内容、依赖环境、数据入口、权重和评估流程；另一条是自行实现核心方法，重点检查论文是否交代了关键细节，以及哪些模块需要重新开发。两条路径会分别给出难度判断，因为跑通现有代码与从论文实现方法，所需工作往往不同。

报告还会说明预计需要的数据、GPU 或显存、时间和人力，并写清估计依据。对暂时查不到的信息，会标记为未知，而不是给出看似精确的数字。

如果原始数据或某个工程部件无法获得，Skill 可以提出替代路线，并说明替代后还能验证什么。核心机制若被替换，结果会归为近似验证，不称为原方法复现。

## 你会得到什么

一次评估包括简短结论、证据和未解决的问题、最低可行验证路径、主要资源需求与难点，以及建议先做的下一步。目标可以是运行作者代码、验证核心方法、接近论文指标，或将方法用于自己的任务；没有特别说明时，默认以验证核心方法为目标。这几种结果会分别判断，不会因为代码能运行就推断论文指标也能复现。

公开资料能支持可行性评估，实际跑通则需要运行记录。小规模安装或试跑是可选的第二阶段，会在任务明确要求时进行。

## 评估怎样进行

Skill 会先固定论文版本、仓库版本、本次目标和可用资源。随后建立证据表：每项发现都注明来源，并区分作者声明、已经检查的文件、实际运行结果和仍然未知的内容。对作者代码，它会从环境与配置追到数据、模型入口和指标；对自行实现，它会检查核心机制、训练目标及论文未写清的实现决定。

难度结论有低、中、高、受阻和待核实五种。等级并非按缺失文件数量打分，而是看缺口是否影响本次目标、能否用常规调试补足，以及资源是否在你的约束内。判断方法和核查项目写在 [核查与判定指南](references/assessment-guide.md)，报告结构见 [模板](assets/report-template.md)。

如果已经有仓库的本地检出，可以运行下面的脚本，先找出环境文件、配置、运行入口和权重文件的候选位置：

```text
python scripts/inspect_repo.py <本地仓库路径>
```

脚本只盘点文件名。是否能运行、数据是否可用、指标是否正确，仍需查看内容或实际验证。

## 如何使用

将本仓库文件夹放入 Codex 的个人 Skill 目录，或项目的 `.codex/skills/` 目录。之后可以这样提问：

```text
$stonelab-reproduction-assessment 评估这篇论文的复现难度：<论文链接或项目仓库>
```

如果你有可用的 GPU、时间预算或指定数据集，也可以一起提供。这些约束会影响难度和推荐路径。完整的评估流程见 [SKILL.md](SKILL.md)。
